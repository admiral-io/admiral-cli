## 🔴 Critical Priority

- [x] **[SECURITY]** `credentials.Save` does not restore `0600` on an existing file. `os.WriteFile` applies the mode only at creation, so a `credentials.json` that was ever widened (or copied from elsewhere) keeps its mode on every refresh, and the CLI then rewrites a fresh refresh token into a world-readable file while only warning on load. `internal/credentials/credentials.go:193-205`. Fix: write to a temp file in the same directory with `0600`, `fsync`, then `os.Rename` over the target. That also makes the write atomic (see next item).
- [x] **[BUG]** Session refresh is not safe under concurrent invocations. Two `admiral` processes started together (a script, a Makefile with `-j`, an editor plugin) both read the same refresh token, both call the token endpoint, and the second is refused because the server rotates refresh tokens (`reuse-refresh-tokens: false`). The loser then reports "session expired" and the *winner's* persisted token is the only valid one, so whichever process wrote last decides whether the session survives. `internal/credentials/credentials.go:refreshSession`. Fix: take an exclusive file lock (`flock` on a `credentials.lock` beside the file) around read-refresh-write, and re-read the file after acquiring the lock so a process that lost the race uses the winner's fresh token instead of refreshing again.

- [x] **[SECURITY]** *pass 2* `--insecure` disables TLS instead of relaxing verification. `internal/client/client.go:58` folds `opts.Insecure` and `opts.PlainText` into one boolean that both the SDK path (`ConnectionOptions.Insecure`) and the session path (`insecurecreds.NewCredentials()`) treat as "no TLS". The flag is documented as "skip server certificate and domain verification", so a user pointing at a self-signed staging host with `-i` believes the token is encrypted in transit when it is sent in cleartext. Today this mostly fails loudly because a TLS listener rejects the plaintext handshake, but any h2c-capable endpoint on the same port would accept it silently. Fix: keep the two flags distinct. `--plaintext` maps to no transport credentials; `--insecure` maps to `credentials.NewTLS(&tls.Config{MinVersion: tls.VersionTLS12, InsecureSkipVerify: true})` on the session path and to `ConnectionOptions.TLSConfig` with the same on the SDK path. `RequireTransportSecurity` on `bearerToken` must then follow plaintext only. Add a `bufconn`-style test asserting the three modes produce the expected transport credentials.

## 🟠 High Priority

- [x] **[BUG]** (found by the new `bufconn` test) The 401 retry sent two `authorization` headers. grpc-go appends every connection-level credential to every call, so adding a per-call credential on retry did not replace the SDK's fixed token, it joined it, stale first. Fixed by giving sessions a CLI-owned connection with a swappable bearer credential (`internal/client/session.go`); later calls now use the refreshed token too. Proper home for this is an SDK `Config` hook for dynamic credentials, which goes through admiral-protos.

- [x] **[SECURITY]** User-supplied names are interpolated into the server filter DSL without escaping: `fmt.Sprintf("field['name'] = '%s'", name)` in `internal/util/resolve.go:38,131,178` and both key and value in `BuildLabelFilter` (`internal/util/labels.go:77`). A name containing `'` breaks the query at best and widens it at worst (`x' OR field['name'] != '`). The client-side re-check in `Resolve` limits the blast radius for name lookups, but `BuildLabelFilter` results are used as-is. Add one `quoteFilterValue` helper that escapes per the DSL's rules (confirm them against the server's filter lexer; it could not be located in the sibling repos during this review) and route every interpolation through it.
- [x] **[BUG]** `credentials.Save` is not atomic. A crash or Ctrl+C during the write leaves a truncated `credentials.json`, which then fails to parse and reads as "not authenticated" with the refresh token lost. Same fix as the `0600` item: temp file plus rename.
- [x] **[TESTING]** No test drives `client.CreateClient` through a real gRPC connection. The interceptor chain (deadline, 401 refresh, transient retry) and its ordering are only unit-tested in isolation with fake invokers. Add one `bufconn`-backed test that starts an in-process server, returns `Unauthenticated` once, and asserts the refreshed token arrives on the retry and that the deadline is present on the server side. `internal/client/`.
- [x] **[BUG]** `output.FormatLabels` iterates a map, so column output and JSON-to-table comparisons are non-deterministic across runs. Sort keys before joining. `internal/output/table.go:33-47`. Also affects test stability for any command that prints labels.

- [x] **[BUG]** *pass 2* `session.go` ignores `Options.Verbose`. The SDK path installs `NewSlogLogger` when verbose; the session path has no logger, so `-v` shows nothing about connection state for signed-in users. Either drop the SDK logger too (interceptors already `slog.Debug`) or add a `grpc.WithChainUnaryInterceptor` debug logger shared by both paths. `internal/client/session.go:60-75`, `client.go:83`.

## 🟡 Medium Priority

- [x] **[BUG]** *pass 2* `op read` runs with no stdin and captured stderr, so if the 1Password CLI needs to prompt (no desktop-app integration, expired `op signin`), the prompt is swallowed and the user sees only the captured text as an error. `internal/credentials/ref.go:35-47`. Pass `cmd.Stdin = os.Stdin` and tee stderr to the terminal when it is a TTY, or document that `op` must be non-interactive (service account or app integration) and detect the "not signed in" case to say so.
- [x] **[BUG]** *pass 2* `credentials.Delete` unlinks `credentials.lock` while another process may hold it. The holder keeps its lock on the unlinked inode; a third process then creates a fresh lock file and the two no longer exclude each other. Window is a logout racing a refresh, so tiny, but the fix is free: leave the lock file in place (it holds nothing) and only remove `credentials.json`. `internal/credentials/credentials.go` `Delete`.

- [x] **[BUG]** `output.Truncate` panics when `max < 3` (`s[:max-3]` with a negative index). Guard with `if max <= 3 { return s[:max] }` or similar. `internal/output/table.go:69-74`. Also rename the parameter; lint flags `max` as shadowing the builtin.
- [x] **[REFACTOR]** `input.ResolveSecret` and `input.FromFlagOrStdin` read `os.Stdin` directly while `input.PromptLine` reads `cmd.InOrStdin()`. The first two cannot be tested without touching the process's real stdin and behave differently from the third when a caller injects a reader. Route all three through `cmd.InOrStdin()`. `internal/input/input.go:51-100`.
- [x] **[REFACTOR]** Two TTY checks with different semantics: `util.isTerminal` requires a concrete `*os.File` (`internal/util/confirm.go:70`), `input.PromptLine` accepts anything with `Fd()`. Consolidate on the `Fd()` form in `input.IsTerminal` and have `util.Confirm` use it.
- [x] **[BUG]** `auth login` waits forever if the user never completes the browser flow. Only Ctrl+C ends it. Add an overall deadline, 5 minutes is conventional, with a clear message. `internal/auth/login.go` around the `select` on `resultCh`.
- [x] **[STYLE]** `credentials.warnIfPermissive` and `ProactiveRefresh` failures log through `slog` with the default text handler, which prints timestamps and `WARN` prefixes that look nothing like the rest of the CLI's stderr output (seen in smoke tests: `2026/09/13 19:39:21 WARN credentials file has insecure permissions ...`). Either configure a plain handler at startup or write user-facing warnings via `output.Writef` to stderr. `internal/credentials/credentials.go:310`.
- [x] **[PERFORMANCE]** `ProactiveRefresh` runs in `PersistentPostRun` for every command, including ones that never touch the network (`config list`, `completion`, `version`, `auth status`). It reads and parses the credentials file each time. Skip it unless the command actually created a client, or gate on a flag set by `CreateClient`. `cmd/root.go` + `internal/credentials/credentials.go:156`.
- [x] **[BUG]** `client.CreateClient` ignores its `ctx` parameter and dials with `context.Background()`. Pass the caller's context so an interrupt during dial is honored. `internal/client/client.go:36,66`.
- [x] **[TESTING]** `internal/util/path.go` (`ExpandPath`) has no tests. Cover `~`, `~/x`, `~user/x` (unsupported, returned as-is), and a plain path.
- [x] **[TESTING]** `credentials.ResolveToken` has no test for a corrupt or truncated `credentials.json`; today that surfaces as a parse error wrapped in "reading credentials". Decide whether that should read as "not authenticated" with a hint to log in again, and pin it.
